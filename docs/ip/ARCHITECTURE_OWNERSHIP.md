## 1. Proprietary Architecture Principles

TravelOS is engineered as a commercial multi-tenant SaaS platform. The software architecture separates the **Platform Infrastructure and Engine** from **Tenant Business Data**.

```
┌─────────────────────────────────────────────────────────────┐
│                    TRAVEL OS PLATFORM                       │
│  [Proprietary Software Engine owned by Platform Operator]   │
│                                                             │
│   ├── Multi-Tenant Kernel & Security Engine                │
│   ├── Universal Travel Domain Models & Services             │
│   ├── Operations, Concierge & Messaging Pipeline            │
│   ├── Financial Ledger & Margin Protection Framework        │
│   └── Dynamic White-Label Visual Theme Generator            │
└──────────────────────────────┬──────────────────────────────┘
                               │ Serves via Isolation
         ┌─────────────────────┼─────────────────────┐

  [Tenant #001: Travia]  [Tenant #002: Agency B] [Tenant #003: Agency C]
  • Owns their data      • Owns their data       • Owns their data

  • Receives SaaS access • Receives SaaS access  • Receives SaaS access
  • NO source code ownership for tenants
```

## 2. Source Code Access Model

1. **Standard SaaS Customers:**
   - Normal travel agencies, DMCs, and concierge operators receive runtime access to the CRM web application, mobile app binaries, client portal, and authorized API endpoints.
   - Standard tenants **do not receive source code ownership, repository access, or IP transfer**.
2. **Enterprise & Founding Partners:**
   - Where dedicated database instances or custom integrations are provisioned, integration occurs via REST API v1, webhooks, and headless SDKs.
   - The core git repository remains strictly under the ownership of the TravelOS platform entity.

## 3. Separation of Platform IP vs Client Data

| Domain Element | Ownership | Rights & Custody |
| :--- | :--- | :--- |
| **Source Code & Architecture** | Platform Operator | Exclusive, proprietary, all rights reserved. |
| **Database Migrations & RLS** | Platform Operator | Platform IP defining the relational model. |
| **Customer Records & PII** | Tenant Company | Tenant retains legal ownership; protected by tenant isolation. |
| **Supplier Agreements & Margins** | Tenant Company | Tenant business secret; protected from customer access. |
| **Trip & Itinerary Content** | Tenant Company | Generated by tenant staff for their respective clients. |
| **Platform Telemetry & Metrics** | Platform Operator | Anonymized performance and system health analytics. |

---

## 4. Tenant Portability & Exit Protocol

Should a tenant terminate their TravelOS subscription:
- TravelOS provides automated, complete data export in standard open formats (CSV / JSON) including all customers, trips, bookings, payment ledgers, and notes.
- In accordance with data privacy regulations (GDPR, UAE Data Protection Law), tenant data is retained during a 30-day grace period before cryptographic deletion upon tenant request.
- At no point is platform source code transferred upon subscription termination.
